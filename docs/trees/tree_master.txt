# /llm_harness/docs/trees/tree_master.txt
/llm_harness (Source of the LLM coding harness: one stdlib Python CLI, the workflow rules it prints, and installers that copy both into ~/.llm_harness)
├── .gitignore (Keeps machine-local harness state out of git; .llm_harness/goal.md and notes.md stay tracked)
├── harness.py (Declarative patch / probe / search / run / undo / git CLI; reads one payload from stdin per run; git and no-git workspaces)
    ├── # Stage: IO helpers (Byte-exact file IO keeping EOL style, BOM and undecodable bytes; payload decoding with UI-safe sentinels; workspace path guard)
    ├── # Stage: Line-1 header and tree glyphs (Inserts the /<project>/<path> first-line comment below shebangs; turns ASCII tree connectors into box glyphs)
    ├── # Stage: Scope resolution (Finds Python/Go/JS/TS/Vue definitions and block bounds; resolves Class.method, Parent > # Stage and tree node paths)
    ├── # Stage: Matching (Applies a hunk only where OLD CODE matches exactly once, scope first then file, with indentation-tolerant fallback; prints on-disk excerpts on failure and says when a one-line OLD CODE is only part of a line)
    ├── # Stage: Syntax checks and rollback (Compiles Python and gofmt-checks Go, restoring the pre-script file on errors; runs go build and prunes unused imports)
    ├── # Stage: Payload parser (One state machine for every directive; flags malformed hunks; holds the @INIT_DEBUG ledger skeleton)
    ├── # Stage: Executing file operations (Applies hunks, count-locked @TEXT_REPLACE edits and file ops in memory, writes once, checks syntax, prints the scorecard, next-step hints and TREE SYNC REMINDER)
    ├── # Stage: Journal and undo (Per-script journal with pre-image snapshots; @UNDO restores snapshots or reverse-applies hunks)
    ├── # Stage: Git (@GIT_INIT creates the repository with an optional identity and default .gitignore and carries numbering and undo history into git mode, also automatically after a hand-typed git init; status report; pre-flight-guarded path-scoped commits and unpushed-commit folding that restore HEAD on any failure; commits may include .llm_harness/goal.md, notes.md and .gitignore)
    ├── # Stage: Read-only directives (Workspace file enumeration, directory listings, @XREF dispatch and whole-word text references)
    ├── # Stage: Code graph (optional codebase-memory-mcp backend) (callers / callees / impact through the CBM CLI with a labelled text fallback)
        ├── run_cbm() (One-shot CBM CLI call; CBM keeps every project's index in its per-user cache, so a moved or cloned project rebuilds its index instead of carrying it)
        ├── workspace_stamp() / index_gaps() / print_coverage_note() / ensure_graph_index() (Re-indexes only when source files changed, records the files CBM parsed only partly, and warns on graph answers that could miss links inside them)
        └── graph_xref() (Runs trace_path, resolves shared names, falls back to text matches labelled NOT proven)
    ├── # Stage: File and text search (@FIND by name or glob; @GREP by text or regex with an optional path filter)
    ├── # Stage: Running commands (@RUN in PowerShell or bash with timeout, process-tree kill and head/tail output, refusing history-changing git; also the TOC, tree, tree drift check, unused-code, scope-references and scope/lines probe printers (Lines and Scope reads feed the inspection log behind [REVISIT] and show the @VERDICT conclusions covering them; @VERDICTS lists them with tree descriptions and stale detection; Tree probes overlay <<verdict>> marks; @CAMPAIGN gives a sweep its verdict legend, footer line and [L1-Campaign] rule until @CAMPAIGN_END removes its verdicts), and the call-site search behind callers)
    └── # Stage: Entry point (Machine-local state, harness-assigned script numbers and a merged state save under a cross-process lock, the @SESSION registry with each session's own aim shown first in the footer and @SCOPE write scopes: overlaps refused, file changes inside another session's scope refused, @RUN changes there reported, scope changes announced once to the other sessions, undo kept inside the session, fold blocked; uncommitted work owned per session (release and commit guards, shared-file warning, explicit hand-over); @MESSAGE, @SCOPE_REQUEST and @BRAKE / @BRAKE_ACK between sessions; the user's --grant, --release and --unbrake commands; saved run output that replays on an identical re-paste unless the script is @REPEATABLE (read, search and @RUN only), @SIDE scripts outside the numbering, the goal kept in .llm_harness/goal.md so it travels with the project, per-directive and total run timings, a nudge when a script only did git work, footer with the user's notes, mode-filtered L1 lines and the full command list, @HELP answered from the syntax card, workspace mode switch, notes, syntax card, handshake and main)
├── README.md (Human guide: why a chat-interface harness, the paste loop, install, sessions, directives, safety model, memory, optional CBM, rules)
├── setup.cmd (Windows installer: copies harness.py and workflow_commands.txt into %USERPROFILE%\.llm_harness with a timestamped backup, offers a CBM install or update, and always ends with a status line and a pause)
├── setup.sh (POSIX installer: same steps as setup.cmd using curl or wget; a finish handler prints the status and pauses in terminals, NO_PAUSE=1 skips it)
├── /tests (Harness self-tests, run through @RUN)
    ├── campaign_test.py (A campaign's legend tags verdicts, its footer line and [L1-Campaign] rule show only while it runs, Tree probes overlay verdicts and stale marks, side scripts are refused, and ending it removes only its verdicts)
    ├── concurrency_test.py (Starts many harness processes at once against a temporary workspace and checks that every script got a unique number, the state stayed consistent and every change landed)
    ├── handoff_test.py (Session aims, release and commit guards for uncommitted work, hand-over, shared-file warning, messages, scope requests, the brake and the user's --release / --unbrake, in a git workspace)
    ├── repeat_test.py (@REPEATABLE scripts run on every paste with fresh numbers, ordinary identical scripts still replay, and repeatable scripts cannot change files or carry a number)
    ├── revisit_test.py ([REVISIT] for rereads of unchanged definitions across ranges, scopes, sessions and side scripts; silence for changed code and within one run)
    ├── scopes_test.py (Two sessions with write scopes: overlap refusal, one-time announcements, refused edits into another scope, @RUN alerts, the user's grant, session-limited undo, scope release)
    ├── text_replace_test.py (Count-locked @TEXT_REPLACE: edits inside a long line, insert and trim, folder-wide import paths, refusals for wrong counts, ambiguity, short or multi-line text, #Class.method scopes, undo and session scopes)
    └── verdict_test.py (@VERDICT on folders, files and definitions; @VERDICTS with tree descriptions, collapsed children, stale detection and filters; verdicts shown on reads; refusals and clearing)
├── workflow_commands.txt (Workflow rules the AI follows; its L1 Rule lines are printed by the harness after every run)
    ├── #* Utility setup (Install checklist and session start)
    ├── #* Turn manifest & standing rules (11-label manifest with Talk and the goal line with the session aim; [L1-Harness], [L1-Sessions])
    ├── #* Optimal code rules ([L1-Scope], [L1-Notes], micro-hunk format)
    ├── #* Tree structure definition (Level-by-level lookup, same-script tree sync, and how the tree and the CBM code graph divide the work)
    ├── #* Git version control & commit rules ([L1-Git Gate], printed for git projects only)
    ├── #* External verification & hallucination gate ([L1-No-Guess], [L1-Evidence])
    ├── #* Knowledge base curation & master registry ([L1-Knowledge])
    └── #* Anti-loop debug ledger & functionality checklist ([L1-Debug])
├── /docs/knowledge (Verified Tech Knowledge Bases)
└── /docs/debug (Active Bug & Checklist Ledgers)
